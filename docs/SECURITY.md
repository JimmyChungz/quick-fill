# 安全设计与边界

## 密码库

逻辑记录仍为 schema v1；持久层支持格式为 qf-vault/version1 的密文封装。使用浏览器 Web Crypto：PBKDF2-SHA256、600000次迭代、每库随机16字节salt；AES-256-GCM、每次写入随机12字节IV、128位认证标签。格式/算法参数/salt作为AAD认证。拒绝不支持的参数、额外字段、不规范base64与超限密文。每个主密码8至1024字符，不裁剪空格。

主密码不持久保存。派生的完整解锁材料仅在 chrome.storage.session 的受信任上下文内存区域中存放；它是敏感密钥，不能被记录、导出或存入local。会话为15分钟绝对期限，不因后台唤醒续期；重载/重启后锁定。应用层加密保护锁定后的静态数据，不能抵御解锁状态恶意扩展执行或设备进程控制，也不提供历史密文防回滚证明。弱主密码仍面临离线猜测。

## 迁移与恢复

旧库保留明文模式直至用户显式设置主密码。加密候选和恢复副本先解密验证，再切换当前数据；失败不自动初始化空库。损坏的当前库不能阻止恢复经过认证、逻辑校验通过的备份，必要时原始损坏结构仅保留在私有加密取证副本。该副本不一定是可直接导入的正常记录库。

主密码变更重新派生并加密当前数据与内部正常备份；用户此前导出的旧文件仍依赖原密码。旧程序不能读取密文，不应通过恢复旧运行目录把新数据覆盖为空。清空已加密库后仍保持加密模式。

## 权限和内部消息

管理/批量读取/导入导出/清空/密钥操作只接收本扩展精确页面来源。网页内容请求要求本扩展ID、顶层frame、有效tab和HTTP(S) origin。网页获得无密码的本站摘要，身份只含字段名；选填请求只返回一条匹配记录。存储访问限制为TRUSTED_CONTEXTS，变更通知不带记录值。所有写入在后台串行，旧代次与冲突修改拒绝。

## 漏洞报告和公开发布

不要在公开Issue提交真实凭据、主密码、浏览器存储或原始导出。公开仓库创建后应由维护者启用私密漏洞报告渠道；当前公开仓库为https://github.com/JimmyChungz/quick-fill，未指定专用安全邮箱；私密漏洞报告功能须在GitHub远端另行核验。源码包、工作树与Git历史扫描仅能发现已知模式，不保证没有任何秘密。个人恢复资产永不作为普通源码公开。

参考：Chrome Storage API https://developer.chrome.com/docs/extensions/reference/api/storage；Web Crypto https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API；OWASP Password Storage Cheat Sheet https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html。

清空所有会清除当前记录和扩展内部恢复副本，外部导出文件与系统/浏览器历史副本不会被自动删除或加密。

## 0.5.0 网页内解锁与分级能力

活跃顶层HTTP(S)内容脚本只能申请短期解锁挑战，不接触主密码。独立chrome-extension来源iframe输入密码，直接向worker提交。worker串行核对扩展ID、frame、精确unlock.html来源、nonce、tabId、当前标签页origin、库代次、2分钟期限和5次尝试上限。成功后清除全部挑战。跨来源同源策略隔离输入与键盘事件；closed shadow只是封装，不能保证页面不遮挡、仿造或删除界面，不能据此承诺防钓鱼。nonce/status可被父页面观察但不包含密码或密钥。页面关闭后遗留挑战到期失效，不存主密码。

只有options可用完整管理能力；popup仅能列表/选定记录修改删除/最近使用/库状态；diagnostics只允许有限诊断接口；unlock页面仅能兑换自身挑战，不能借iframe获得管理/导出/密钥能力。锁定或代次变化清除内容脚本的待保存秘密；普通其他标签页写入保留独立提示。

local容量预检使用实际QUOTA_BYTES和getBytesInUse，按UTF-8 JSON保守估算更新与恢复副本，使用80%配额上限。该预检不能替代浏览器最终写入异常处理，也不宣称多次storage.set具有数据库事务原子性。迁移首写前预检两个阶段；首写后的平台故障可留下已验证恢复副本，当前主库保持原样。

0.5.1：精确顶层popup.html新增且仅新增qf.vault_unlock能力，以支持工具栏与持久编辑页直接解锁。diagnostics、内容脚本、嵌套popup iframe不能调用此能力；setup/change/restore/export/clear等批量与密钥管理仍不开放给popup。主密码只在扩展DOM与worker请求中短暂存在，提交、失败和pagehide均清空输入，不在消息通知或存储持久保留。

## 0.6.0 持久化、恢复与中断边界

登录密码的保存、更改、JSON导入和确认保存均经worker的credential-policy门禁：未启用Vault时拒绝非空登录密码写入，提示显式设置主密码。旧明文数据不会被静默迁移，仍能读取/填充/导出/删除；身份信息可继续单独管理。最低8字符按用户要求保留，不将它等同强口令。内部repository测试可单独隔离门禁；实际worker集成与浏览器验证覆盖该保护，不允许UI绕过worker写入。

恢复时旧primary必须通过AES-GCM认证和逻辑schema校验，才能被提升为recovery；验证使用匹配的恢复密钥或有效的受信任会话。无法认证时，已有恢复封装保持不变，旧primary仅存入现有的单个加密取证槽；该槽不是可直接导入的普通记录库。

清空先确认加密库可读，再推进代次、撤销候选、删除内部恢复副本，最后提交空primary。已提交的空库后不再有待执行的删除步骤。操作中断在最终提交前可能保留旧primary并需要重试；多次Storage API调用仍不是数据库事务，期间到期或平台故障可能使未完成请求产生部分副作用，不承诺全局原子性。

新增故障注入在setup/restore/change的备份、主库与代次、读回、会话与闹钟边界中断后重载模块验证；它与实际浏览器后台停止/恢复测试分开记录，不把模拟中断冒称逐条真实Chrome worker-kill。

可见性增加文档垂直范围及滚动容器的可到达位置投影；普通缩放换算为渲染坐标。正向大偏移若实际扩展文档且可滚动到，不被谎称文档外；未绑定包含块的fixed字段按viewport判断。任意mask、SVG路径、旋转/反射变换和像素遮挡仍不保证。

## 0.6.1 密码查看、内容版本和兼容读

解锁眼睛只改变扩展自己输入框的显示类型，不复制、不发送和不存储密码值。默认隐藏，输入前/输入/粘贴/拖放/组合输入/change即隐藏，提交/窗口失焦/pagehide/页面不可见也隐藏。完成与异常清理必须先恢复password类型再清空，避免按type=password查找遗漏已揭示的字段。三处解锁表单均复用同一绑定，不改变主密码最低8字符政策。

Profile新增可选lastUsedAt，只用于排序与使用时间；updatedAt继续作为内容修订token，服务端同毫秒修改也推进token。旧库保持schema v1、密文不变，无后台批量数据迁移。新导入/编辑的identity字段严格限定已知非凭据token；兼容读取仅保留旧版已接受的已知credential键，不允许新增或自动填入登录字段，未知键仍fail closed。

填充取得有效记录后，最近使用时间更新可以best-effort；返回秘密前仍重新核对Vault状态、当前代次，并在最后一个await后再次检查绝对到期时间。不能将真正的解锁失效当成可忽略的元数据错误。旧明文提示仅显示条数，迁移仍使用用户自设主密码及既有候选认证/读回机制。

清空中断后的旧primary保留与显式重试边界不变，不在下次启动自动删除用户保留的数据。完成通知postMessage只带nonce和结果，来源/origin/nonce仍校验；通道的有限状态可见性不被描述成密码泄漏。
